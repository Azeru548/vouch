Vouch

Is it real? Scan and know.

Track: FinTech & Commerce (or Civic Tech & Public Good — see Track Fit below)

The Problem

NAFDAC assigns every approved drug, food, cosmetic, and chemical product a registration number as proof it passed safety review. Consumers see these numbers on packaging every day and trust them — but almost nobody can actually check one. NAFDAC's own verification tool is app-only, drug-focused, and not built for a fast, in-store decision. The result: a real safety signal exists, but it's functionally invisible to the person standing in the shop.

Two failure modes make this worse than "just check the number":

  1. No number at all — an unregistered or fully fake product with nothing to verify.
  2. Number cloning — counterfeiters print a real registered number on a different product. A simple "does this number exist" check misses this entirely; you have to confirm the number belongs to this product.

The Solution

Vouch is a consumer-facing scan tool that checks any NAFDAC-registered product — drugs, food, cosmetics, chemicals — against NAFDAC's own registry in real time, and catches both failure modes above.

Core flow:

  1. User scans the NAFDAC number on the pack (camera OCR, manual entry as fallback)
  2. Vouch looks it up against a locally-ingested copy of the full NAFDAC registry
  3. Result is one of three outcomes, not two:
    • ✅ Verified — number exists, product name/manufacturer matches registry
    • ⚠️ Mismatch — number exists but belongs to a different product (likely cloning)
    • ❌ Not found — number isn't in the registry at all
  4. User can report a suspicious product directly from the result screen, building a structured, location-tagged signal over time

Why This, Why Now

  • NAFDAC's registry is real, current, and — per our own technical recon — programmatically accessible with no authentication required
  • Scope is explicitly limited to NAFDAC-registered products only — no unregulated-product visual detection, no scope creep, a claim we can fully back with data
  • One numbering system already spans multiple product categories (drug, food, cosmetic, chemical), so "beyond just drugs" isn't a stretch — it's the same dataset

Target User

Everyday consumers buying medicine, packaged food, or cosmetics from patent medicine shops, open markets, and informal retail — the exact point in the supply chain where counterfeits pass through with the least friction.

Track Fit

Strongest fit is FinTech & Commerce (marketplace/commerce trust tooling) or Civic Tech & Public Good (public safety infrastructure) — both tracks are live options; final call depends on how the pitch frames it (consumer trust tool vs. public-health infrastructure).

Technical Spec

Data Source

  • greenbook.nafdac.gov.ng — confirmed public JSON API (DataTables server-side endpoint), no auth, no rate limiting observed
  • Full registry: 8,977 products
  • Ingested on a scheduled pull (daily or every 2–3 days) into Vouch's own database — consumer lookups never hit NAFDAC live

Ingestion Pipeline

  • Paginated GET requests (length=500 per page) with required X-Requested-With: XMLHttpRequest header
  • Fields captured: NAFDAC reg. number, product name, strength, form, applicant, manufacturer, category, approval/expiry date, status
  • Normalization: lowercase, strip formatting artifacts, collapse whitespace, preserve dosage/units
  • Known constraint: reg. numbers are not unique per row (multiple products can share a prefix/number pattern) — lookup returns all candidate rows for a number, not a single match

Verification Logic

  • Exact reg. number lookup against local DB
  • Candidate product name compared against registry name(s) using token-based fuzzy matching (e.g. RapidFuzz token_set_ratio), handling word-order and formatting differences
  • Manufacturer compared separately from product name — independent scoring gives a sharper counterfeit signal than one blended score
  • Similarity threshold (~80–85%, tuned against real data) determines Verified vs. Mismatch

OCR / Input

  • Primary: camera capture → vision-model API (structured JSON extraction: nafdac_number, product_name, found) rather than classical OCR, for robustness against glare, curved packaging, and inconsistent print position
  • Extracted number regex-validated against NAFDAC's known format before trusting it — vision models can hallucinate plausible-looking codes from blurry input
  • Fallback: manual number entry, always available

Report Feature

  • Structured, not free-text-only: reg. number, scan result at time of report, coarse location (market/area, not precise GPS), optional photo, optional note
  • Reports are a signal, not a public verdict — never displayed as a standalone accusation against a named manufacturer
  • Aggregation threshold (e.g. 3+ independent reports in a time window) before any pattern surfaces in-app
  • Basic spam control via per-device/session rate limiting — no full account system needed for MVP
  • Framed honestly in the pitch: architected to export aggregated, anonymized data in a format regulators could consume — no claimed partnership or integration with NAFDAC

Known Limitations (state these up front, don't get caught out)

  • Registry is a periodic snapshot, not live — a newly-registered product could briefly show "not found"; UI copy must say "not found in our records" rather than "confirmed fake"
  • Scope is registered products only — an unregistered product with no number is out of scope by design
  • Reg. number collisions require the fuzzy-match layer to work correctly; edge cases here are the main technical risk

MVP Build Order

  1. Ingestion pipeline + local DB (data layer proven via recon — low risk)
  2. Lookup endpoint: number → candidate rows → match/mismatch/not-found
  3. Frontend scan flow, OCR wired in with manual-entry fallback
  4. Fuzzy name/manufacturer matching + threshold tuning
  5. Report submission + aggregation view
  6. Buffer for data-quality issues (expect this to eat the most time)

What We're Not Claiming

  • No NAFDAC partnership or endorsement
  • No coverage of unregistered/informal products
  • No guarantee of real-time registry freshness
